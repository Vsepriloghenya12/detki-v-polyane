# Authentication Tabs Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Split the shared entry screen into explicit login and registration tabs with reliable Russian phone normalization.

**Architecture:** Keep the unified root application and existing family endpoint. Add explicit login/registration intent errors on the server, centralize client phone normalization in `src/login.js`, and render tab state inside the existing authentication card.

**Tech Stack:** Node.js HTTP server, React 18, TypeScript, Node test runner, Vite.

- [ ] **Step 1: Add failing normalization tests**

```js
import { loginKind, normalizePhone } from './login.js'

test('phone formats normalize to the same Russian number', () => {
  const expected = '79991112233'
  assert.equal(normalizePhone('+7 (999) 111-22-33'), expected)
  assert.equal(normalizePhone('7 999 111 22 33'), expected)
  assert.equal(normalizePhone('8 999 111 22 33'), expected)
  assert.equal(normalizePhone('9991112233'), expected)
  assert.equal(normalizePhone('999111223'), '')
})
```

- [ ] **Step 2: Run the login test and verify RED**

Run: `node --test src/login.test.js`

Expected: FAIL because `normalizePhone` is not exported.

- [ ] **Step 3: Implement normalization**

Export `normalizePhone(value)` using the existing rules: strip non-digits,
convert leading `8` to `7`, prepend `7` to ten digits, and return an empty
string unless the final value is exactly eleven digits beginning with `7`.
Make `loginKind` call this helper and update the declaration file.

- [ ] **Step 4: Use the shared helper in App**

Remove the local `cleanPhone` function from `src/App.tsx`, import
`normalizePhone`, and use it for parent login, registration, and owner-managed
parent phone submissions.

Run: `node --test src/login.test.js`

### Task 3: Login And Registration Tabs

- [ ] **Step 1: Replace progressive registration state**

Use entry modes `login`, `owner`, and `register`, plus an optional suggested
tab. Unknown parent login stays in `login`, shows `Пользователь не найден`, and
suggests registration. Duplicate registration stays in `register`, shows the
duplicate message, and suggests login.

- [ ] **Step 2: Add explicit tab switching**

Add `selectEntryTab('login' | 'register')` that preserves
`entryIdentifier`, clears stale errors/suggestions, and selects the requested
form. All logout and successful-login paths reset to `login`.

- [ ] **Step 3: Mark registration intent**

Send `register: true` with phone and parent/child fields. Catch
`family_already_exists` to show the login suggestion without activating the
existing household.

- [ ] **Step 4: Render tabs in UnifiedEntry**

Render `Вход` and `Регистрация` buttons with `role="tab"`,
`aria-selected`, and one active state. Login contains `Телефон или логин`; text
login reveals the educator password. Registration always shows phone, parent
name, parent surname, and child name. Render the suggested-tab action directly
below the error.

- [ ] **Step 5: Add compact tab styles**

Style the tab list as a two-column segmented control using existing colors,
radii, and focus states. Do not change the hero or internal app screens.
